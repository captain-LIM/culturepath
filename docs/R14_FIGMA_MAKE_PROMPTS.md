>

>
> **기준 문서:** [R14 Manus 프로토타입 프롬프트](./R14_MANUS_PROTOTYPE_PROMPTS.md) · [R14 P0 디자인 명세](./R14_FIGMA_P0_DESIGN_SPEC.md) · [R14 디자인 검수표](./R14_DESIGN_REVIEW_CHECKLIST.md) · [R14 최종 결과와 R15 인계](./R14_MANUS_PROTOTYPE_RESULT.md)

## 1. 사용 방법

1. 먼저 [Manus 프로토타입 프롬프트](./R14_MANUS_PROTOTYPE_PROMPTS.md)를 끝까지 실행하고 화면을 승인한다.
2. Manus의 390px 핵심 캡처, 360·430px 대표 변형, `DESIGN_SYSTEM.md`, `STATE_MATRIX.md`, `FIGMA_HANDOFF.md`를 Figma 작업의 참고자료로 준비한다.
3. 새 Figma Make 작업에서 **0번 공통 기반 프롬프트**를 한 번만 입력한다.
4. 1번부터 5번까지는 Manus 승인 결과와 다른 화면만 선택해 사용한다. 이미 승인된 화면을 불필요하게 재생성하지 않는다.
5. 6번 핸드오프 정리와 필요한 교정 프롬프트에 남은 무료 AI 크레딧을 우선 사용한다.
6. 각 단계가 끝날 때 [검수표](./R14_DESIGN_REVIEW_CHECKLIST.md)로 확인하고, 황찬우가 승인하기 전에는 Flutter 구현 기준으로 확정하지 않는다.

이 문서는 Manus에서 승인한 디자인을 Figma 변수·컴포넌트·Variant·Auto Layout·Prototype으로 정리하기 위한 후속 프롬프트다. Figma Make가 코드까지 생성하더라도 시각 원본과 상호작용 명세만 사용하며 생성 코드를 저장소에 복사하지 않는다.

## 2. 0번 — 공통 기반과 컴포넌트

아래 블록 전체를 첫 프롬프트로 입력한다.

```text
Google Play에 배포할 Android 모바일 앱 CulturePath의 P0 디자인 시스템과 공통 컴포넌트를 만들어줘.

CulturePath는 사용자가 관심 문화와 지역을 고르고, 실제 관광지를 탐색해 여러 날의 여행 코스를 만드는 서비스다. AI는 대화 상대가 아니라 이미 만든 코스를 조건에 맞게 다듬는 보조 기능이다. 대상 사용자는 문화 취향이 분명하지만 여행 동선을 직접 조사하는 부담을 줄이고 싶은 일반 여행자다.

전체 인상은 '한국의 문화 여행 편집지'다. 종이 위에 실제 여행 사진, 짧은 편집자 주석, 명확한 지명과 일정 순서가 놓인 느낌을 사용한다. 자동 생성 랜딩페이지나 카드 대시보드처럼 보이면 안 된다.

Android 390dp 폭을 기본 프레임으로 하고 360dp와 430dp 변형 규칙도 만든다. status bar, gesture navigation, bottom safe area를 포함한다. 기준 수치는 다음과 같다.
- 색: ink #2B2D42, paper #F7F3E9, surface #FFFFFF, terracotta #C05534, mustard #D9A441, charcoal #1E1E1E, muted #6D6E6D, line #DDD8CE, success #3F6B50, danger #A33D32
- 제목: Noto Serif KR Bold/SemiBold, 본문·버튼·숫자: Noto Sans KR
- 크기: display 28/38, screen title 22/30, section title 18/26, card title 15/22, body 14/22, label 12/18, caption 11/16
- 간격: 4, 8, 12, 16, 20, 24, 32, 40
- 좌우 여백: 360dp는 16, 390dp는 20, 430dp는 24
- 버튼 radius 10, 입력·작은 표면 8, 사진 카드 12
- 터치 영역 최소 44x44dp, 주요 버튼 높이 최소 48dp
- 기본 카드에는 그림자를 쓰지 않고 1dp 선 또는 배경 면 차이로 구분한다.
- 모션은 120~240ms이며 reduce motion에서도 정보가 유지되어야 한다.

Figma 컴포넌트 이름은 CP/AppHeader, CP/BottomNav, CP/CultureTile, CP/CourseRow, CP/FeedCourse, CP/PlaceMediaCard, CP/SegmentedTabs, CP/PrimaryButton, CP/EmptyState, CP/InlineError, CP/AiAssist로 통일해줘. 각 컴포넌트에 필요한 default, pressed, focused, selected, disabled, loading, empty, error, image-missing variant를 실제 필요 범위에서 만들어줘. Auto Layout을 사용하고 고정 폭 대신 min/max와 hug/fill 규칙을 표시해줘.

하단 내비게이션은 홈, 탐색, 만들기, 내정보의 동등한 4개 목적지다. 만들기만 튀어나온 원형 FAB처럼 만들지 않는다.

금지 사항:
- 보라색·네온색·별 반짝임으로 AI를 표현하지 말 것
- 화면 전체 gradient, glassmorphism, 과한 그림자, 큰 둥근 카드의 반복을 쓰지 말 것
- 모든 문구를 pill 안에 넣지 말 것
- emoji와 임의 일러스트로 실제 관광지 사진 부족을 감추지 말 것
- 존재하지 않는 날씨, 가격, 거리, 실시간 혼잡도, 추천 점수, 운영정보를 만들지 말 것
- 지도 고도화와 다국어 기능을 새로 설계하지 말 것

접근성 대비, 긴 한국어 장소명, text scale 1.0·1.3·2.0, 이미지 없음, 로딩, 빈 결과, 오류와 stale 상태가 처음부터 고려된 기반 페이지를 만들어줘. 결과에는 색·타입·간격 변수 표, 컴포넌트 세트, 390dp 샘플 프레임 하나를 포함해줘.
```

## 3. 1번 — 홈

```text
앞서 만든 CulturePath 토큰과 CP 컴포넌트만 사용해서 Android 홈 화면을 설계해줘. 새로운 시각 체계나 하단 탭을 만들지 마.

홈의 목적은 사용자가 문화 취향으로 탐색을 시작하고, 작업 중인 자신의 코스로 빠르게 돌아가게 하는 것이다. 390dp 기본 프레임과 360dp·430dp 대응 메모를 만들어줘.

위에서 아래 순서는 다음과 같다.
1. CulturePath 브랜드 제목과 명확한 검색 진입
2. 한 장의 실제 여행 사진과 짧은 계절 편집 문구를 가진 절제된 계절 추천 영역
3. '오늘은 어떤 문화를 따라갈까요?' 제목 아래 2열 문화 그리드
4. 최대 2개만 보이는 '내 코스 이어보기'와 '전체 보기'
5. 충분한 하단 여백과 CP/BottomNav

문화는 정확히 다음 10개를 사용한다: 독립서점·책방, 문학, 음악, 전통주·양조장, 로컬 미식, 공예·공방, 근대 문화유산, 미술·갤러리, 영화·애니메이션, 커피·카페.

'내 코스 이어보기'는 로그인 사용자의 서버 코스 또는 게스트의 로컬 코스를 같은 시각 문법으로 보여준다. 최근 시각 데이터가 Flutter 모델에 아직 없으므로 '방금 편집', '3시간 전' 같은 문구를 만들지 않는다. 코스가 없으면 '첫 코스 만들기' 한 가지 행동만 제공하고, 로그인 강요 배너를 만들지 않는다. 로딩은 2개 skeleton row, 실패는 해당 섹션 안에서만 재시도하게 한다.

홈에 인기 코스 피드를 다시 넣지 않는다. 공개 코스와 랭킹은 탐색 화면의 역할이다. 계절 추천은 거대한 gradient hero가 아니라 실제 사진, 낮은 채도의 overlay, 지명 또는 편집 문구가 중심이어야 한다. 화면 상단에 원형 AI 버튼을 배치하지 않는다.

기본, 내 코스 없음, 로딩, 부분 오류, 대표 이미지 없음의 5개 상태 프레임을 만들어줘. 모든 문구와 행동은 한국어로 작성하고 터치 영역·텍스트 줄 수·이미지 비율을 개발자 메모로 표시해줘.
```

## 4. 2번 — 탐색

```text
같은 CulturePath 디자인 시스템으로 탐색 화면을 다시 설계해줘. 탐색의 1차 구조는 정확히 '내 코스 / 커뮤니티 / 인기' 3개 탭이며 '내 코스'가 기본 선택이다.

내 코스 탭:
- 로그인 사용자는 GET /courses 기반 자신의 코스를, 게스트는 기기에 저장된 로컬 코스를 본다.
- 행 전체는 코스 상세로 이동하고 편집·삭제는 우측 overflow menu로 분리한다.
- 코스가 없으면 이유를 짧게 알리고 '코스 만들기' 하나만 제안한다.
- 생성일·수정일은 현재 Flutter 모델이 읽지 않으므로 상대 시각을 임의 표시하지 않는다.

커뮤니티 탭:
- 공개 코스 피드를 보여준다.
- '최신 / 인기' 정렬은 Switch가 아니라 동등한 segmented control로 표현한다.
- 실제 가능한 정보인 작성자, 제목, 설명, Day 수, 장소 수, 좋아요를 사용한다.

인기 탭:
- 랭킹 데이터를 1위부터 읽기 쉽게 보여준다.
- 1~3위에만 절제된 mustard 포인트를 사용하고 메달 emoji, 원형 배지 남발, 시상대 일러스트는 쓰지 않는다.
- 나머지는 같은 목록 구조로 이어진다.

각 탭의 loading, empty, error, stale 상태를 별도 프레임 또는 component variant로 만든다. 검색 진입은 유지한다. 무한한 둥근 카드 피드 대신 사진, 얇은 구분선, 여백과 타이포 위계로 묶는다. 360dp에서 탭 텍스트가 잘리거나 터치 영역이 줄지 않아야 한다.

기본 3개 탭 프레임과 핵심 상태 프레임을 만들고, CP/SegmentedTabs와 CP/CourseRow/CP/FeedCourse 인스턴스가 공통 컴포넌트에 연결되게 해줘.
```

## 5. 3번 — 문화·지역·관광지 흐름

```text
같은 CulturePath 시스템으로 '문화 선택 → 지역 추천 → 관광지 목록 → 관광지 상세 → 연관 장소' 흐름을 설계해줘. 지도 기능을 새로 추가하거나 목록을 지도로 전환하지 마.

실제 예시 콘텐츠로 오죽헌, 강릉 오죽헌·시립박물관, 박경리기념관, 통영국제음악당, 통영 중앙시장, 전주 한옥마을을 사용할 수 있다. 다만 이 이름들에 존재하지 않는 운영시간·가격·거리·평점은 만들지 않는다.

문화 상세·지역 추천:
- 선택한 문화명과 짧은 설명
- 추천 지역 순서와 근거를 읽을 수 있는 단정한 목록
- 공개 API에 없는 정밀 점수나 실시간 추천 수치를 만들지 않는다.

관광지 목록:
- 선택한 문화와 지역을 제목에서 명확히 유지한다.
- 장소 사진, 장소명, 주소 또는 제공되는 보조 정보, 독립된 '담기' 행동을 표현한다.
- 카드 사진과 제목은 상세로 이동하고 담기 버튼과 터치 영역이 겹치지 않는다.
- 이미지 URL이 없거나 깨져도 장소명을 읽을 수 있는 종이·잉크색 placeholder를 사용한다.
- 관련성이 검증된 결과만 최대 20개라는 제품 성격을 유지하고, 빈 결과를 가짜 장소로 채우지 않는다.

관광지 상세:
- 최대 10장 이미지 갤러리이지만 0장·1장·여러 장 상태를 모두 고려한다.
- 장소명, 문화 분류, 주소, 운영시간, 휴무, 전화, 주차, 홈페이지, 소개는 값이 있을 때만 표시한다.
- 빈 필드에 '-' 카드를 반복하지 않는다.
- '이 장소를 코스에 담기'를 주요 행동으로 둔다.
- 연관 장소 API 실패가 상세 전체 오류처럼 보이지 않게 하단 섹션만 재시도한다.
- 이미지 영역 하단에 절제된 TourAPI 출처 표기를 둔다.

390dp 기준 흐름 프레임과 loading, 결과 없음, 상세 일부 정보 없음, 이미지 없음, 연관 장소 오류 상태를 만들어줘. nullable 정보의 표시 규칙과 텍스트 최대 줄 수를 개발자 메모에 적어줘.
```

## 6. 4번 — 코스 만들기·보기

```text
같은 CulturePath 토큰과 컴포넌트로 코스 만들기와 코스 상세 흐름을 설계해줘. 기존 기능의 Day·장소·저장·Fork 계약은 유지하고 지도 기능을 확장하지 마.

코스 만들기:
- 코스 제목과 설명
- Day 1~3의 명확한 세로 순서
- 각 장소의 순번, 이름, 지역, 문화 맥락
- 장소 검색·추가, 순서 변경, Day 이동, 제거 행동
- 빈 Day, 장소 검색 중, 저장 중, 저장 실패, 게스트 로컬 저장 상태

코스 상세:
- 제목, 작성자, 설명, Day 수와 장소 수
- Day별 장소 순서
- 소유자는 편집 진입, 다른 사용자는 원본을 보존한 Fork 행동
- 좋아요와 공유는 실제 기능이 있는 범위에서만 표시
- 지도는 현재 구현 위치를 유지하는 중립적인 영역으로만 표현하고, 새 마커 규칙·경로선·목록 연동을 설계하지 않는다.

Day를 각각 큰 둥근 카드 안에 중첩하지 말고 편집지의 일정표처럼 날짜 구분선, 순번, 장소명과 충분한 여백으로 보여줘. 드래그 핸들만으로 행동을 설명하지 말고 접근 가능한 이동 메뉴 또는 라벨을 함께 둔다. 저장 성공을 과한 축하 화면으로 만들지 않는다.

390dp 기본 화면, 360dp 긴 장소명, 430dp 화면, 빈 코스, 저장 중·실패, Fork 확인 상태를 만들어줘. 키보드가 열린 상태에서도 현재 입력과 저장 행동이 가려지지 않는 규칙을 메모해줘.
```

## 7. 5번 — AI 코스 다듬기

```text
같은 CulturePath 디자인 시스템으로 기존 코스를 AI로 다듬는 전체 화면 흐름을 설계해줘. AI 챗봇이나 자유 대화 화면으로 바꾸지 마.

흐름은 다음 순서를 지킨다.
1. 사용자가 'AI로 다듬기'를 선택한다.
2. 원하는 조건을 한 번에 입력한다.
3. 처리 중에도 원본 코스가 보존된다는 문구를 보여준다.
4. 결과를 바로 덮어쓰지 않고 요청 요약과 변경 제안을 먼저 보여준다.
5. 추가·제거·이동·유지된 장소를 색만이 아니라 아이콘, 라벨, 설명으로 구분한다.
6. 사용자가 적용 또는 취소를 선택한다.
7. 적용 뒤에도 원본 복구 경로를 명확히 보여준다.

AI 표현은 CP/AiAssist와 'AI로 다듬기'라는 언어에 한정한다. 보라색, 별, 마법봉, 빛나는 gradient를 쓰지 않는다. 주요 시각 정보는 코스 제목, Day, 장소 변화와 경고다.

다음 상태를 각각 설계해줘: 입력 전, 처리 중, 변경안 성공, 변경 없음, 일부 장소 검증 실패, RAG 검색 실패, OpenRouter 오류, 적용 중, 적용 완료, 취소·원본 복구 확인. 기술 공급자 이름이나 내부 오류 코드를 그대로 사용자에게 노출하지 말고, 재시도 가능 여부와 원본 안전성을 설명한다.

390dp 프레임과 text scale 2.0에서 긴 변경 설명이 잘리지 않는 변형을 만든다. 적용과 취소의 우선순위, 위험 행동 확인, disabled/loading 상태를 개발자 메모로 표시해줘.
```

## 8. 6번 — 상태·반응형·핸드오프 정리

```text
지금까지 만든 CulturePath 프레임 전체를 구현 핸드오프 가능한 상태로 정리해줘. 새 디자인을 제안하지 말고 기존 CP 토큰과 컴포넌트 인스턴스만 정규화해줘.
```

## 9. 결과가 어긋났을 때 쓰는 교정 프롬프트

### 시각이 흔한 AI 앱처럼 보일 때

```text
새 화면을 만들지 말고 현재 화면을 교정해줘. 보라색·gradient·유리 효과·과한 그림자·원형 AI 장식과 불필요한 pill을 제거한다. 큰 둥근 카드의 반복을 줄이고 paper 배경, 실제 사진, 얇은 구분선, Noto Serif KR 제목과 Noto Sans KR 본문의 편집지 위계로 다시 정리한다. 정보와 행동은 유지하고 장식만 절제한다.
```

### 정보나 기능을 임의로 만들었을 때

```text
현재 CulturePath 구현에 없는 날씨, 가격, 거리, 실시간 혼잡도, 별점, 추천 점수, 운영정보, 지도 기능, 다국어 기능을 모두 제거해줘. 값이 nullable인 관광 정보는 있을 때만 보이고 없으면 섹션을 생략하거나 명확한 빈 상태를 사용한다. 실제 데이터가 없는 자리를 가짜 정보로 채우지 않는다.
```

### 컴포넌트가 화면마다 달라졌을 때

```text
현재 프레임의 독립 스타일을 제거하고 00_Foundations와 01_Components의 변수·CP 컴포넌트 인스턴스로 교체해줘. 동일 역할은 동일한 padding, radius, type style, 상태 이름을 사용한다. 시각 결과는 유지하되 detached component와 임의 색·간격 값을 남기지 않는다.
```

### 작은 화면이나 큰 글자에서 깨질 때

```text
360dp Android 프레임과 text scale 2.0에서 다시 검토해줘. 터치 영역은 줄이지 않고 보조 문구의 줄 수와 배치를 조정한다. 제목과 주요 행동은 유지하고 가로 스크롤, 잘린 탭, RenderFlex overflow가 생길 구조를 제거한다. safe area와 키보드가 열린 상태도 표시한다.
```
