- `차단`: 하나라도 실패하면 R14를 완료하거나 R15를 시작하지 않는다.

## 3. 정보구조·기능 계약

### 홈

- [ ] 검색, 계절 편집 영역, 문화 10종, 내 코스 이어보기가 정해진 순서로 보인다.
- [ ] 문화 10종의 명칭이 디자인 명세와 정확히 일치한다.
- [ ] 내 코스는 로그인 서버 코스와 게스트 로컬 코스를 모두 수용한다.
- [ ] timestamp 미지원 상태에서 `방금 편집` 같은 가짜 상대 시각이 없다.
- [ ] 내 코스 없음·로딩·부분 오류가 홈 전체를 막지 않는다.
- [ ] 원형 AI 버튼이 홈의 주인공처럼 보이지 않는다.

### 탐색

- [ ] `내 코스 / 커뮤니티 / 인기`의 목적 차이가 한눈에 이해된다.
- [ ] 커뮤니티의 최신·인기는 Switch가 아닌 동등한 segmented control이다.
- [ ] 내 코스 행 진입과 overflow 편집·삭제 터치 영역이 분리된다.
- [ ] 랭킹 1~3위와 나머지가 과장 없이 구분된다.
- [ ] 각 탭에 loading·empty·error·stale 상태가 있다.

### 문화·지역·장소

- [ ] 선택한 문화와 지역 맥락이 다음 화면에서도 유지된다.
- [ ] 관광지 목록은 실제 관련 장소만 최대 20개라는 계약과 충돌하지 않는다.
- [ ] 빈 결과를 가짜 장소나 Mock seed로 채우지 않는다.
- [ ] 장소 카드의 상세 진입과 코스 담기 행동이 분리된다.
- [ ] 상세의 nullable 필드는 값이 있을 때만 보이고 `-` 표면을 반복하지 않는다.
- [ ] 0장·1장·여러 장 갤러리와 깨진 URL 상태가 있다.
- [ ] 연관 장소 실패가 상세 전체 실패로 표현되지 않는다.
- [ ] TourAPI 이미지·정보 출처가 과하지 않게 표시된다.

### 코스·AI

- [ ] Day와 장소 순서가 장식보다 먼저 읽힌다.
- [ ] 빈 Day·검색·저장 중·저장 실패·게스트 저장 상태가 있다.
- [ ] 소유자 편집과 타 사용자 Fork 행동이 구분된다.
- [ ] AI는 자유 대화가 아니라 기존 코스 변형 보조로 표현된다.
- [ ] 추가·제거·이동·유지가 색 이외의 라벨이나 아이콘으로도 구분된다.
- [ ] AI/RAG 실패 때 원본 보존, 재시도 가능 여부와 다음 행동을 알 수 있다.

## 4. 실제 데이터와 콘텐츠

- [ ] 장소명·코스명이 두 줄까지 길어져도 주요 행동을 밀어내지 않는다.
- [ ] 주소·소개·운영정보가 긴 경우의 최대 줄 수와 상세 표시 규칙이 있다.
- [ ] `createdAt`·`updatedAt` 등 현재 Flutter가 읽지 않는 필드를 시각 문구로 가정하지 않는다.
- [ ] 사진은 TourAPI HTTPS 이미지, 안전한 캐시, placeholder 계약으로 교체 가능하다.
- [ ] Manus·Figma가 생성한 사진을 라이선스 확인 없이 앱 에셋으로 간주하지 않는다.
- [ ] `contentId`가 화면에서 보이지 않더라도 상세·담기·RAG 동일 장소 식별에 유지된다.
- [ ] 한국어 고정 문구만 기준으로 레이아웃을 과도하게 고정하지 않는다.
- [ ] 다국어 표시는 임수민 구현 후 긴 문구 통합 QA 대상으로 남는다.

## 5. 비-AI형 시각 언어

- [ ] 실제 여행 사진, 지명, 일정과 편집 주석이 시각 위계를 만든다.
- [ ] 화면 전체 gradient가 없다.
- [ ] 보라색·네온·별·마법봉이 AI의 기본 상징으로 사용되지 않는다.
- [ ] glassmorphism과 과도한 blur가 없다.
- [ ] 모든 섹션이 같은 큰 둥근 카드로 반복되지 않는다.
- [ ] 기본 카드에 강한 그림자가 반복되지 않는다.
- [ ] pill은 선택·필터·상태에만 사용한다.
- [ ] emoji와 장식 일러스트가 실제 정보나 빈 상태를 대신하지 않는다.
- [ ] 한 화면의 terracotta 주요 CTA가 경쟁하지 않는다.
- [ ] Noto Serif KR은 제목 중심, Noto Sans KR은 본문·숫자 중심으로 절제되어 있다.

## 7. 컴포넌트·Flutter 핸드오프

- [ ] 페이지가 `00_Foundations`부터 `08_Handoff`까지 정리되어 있다.
- [ ] 색·타입·간격·radius·elevation이 변수나 스타일로 정의되어 있다.
- [ ] 공통 UI는 `CP/...` 컴포넌트 인스턴스이며 detached 복제본이 아니다.
- [ ] default·pressed·focused·selected·disabled·loading·error variant가 실제 필요 범위에 있다.
- [ ] Auto Layout의 hug/fill, min/max 폭과 높이가 기록되어 있다.
- [ ] padding, gap, radius, line height, 최대 줄 수가 명확하다.
- [ ] 이미지 fit, 비율, 최대 decode 표시 크기와 missing/error 상태가 있다.
- [ ] 화면별 API 필드와 정적 카피가 구분되어 있다.
- [ ] nullable 필드의 숨김·fallback·placeholder 규칙이 있다.
- [ ] Prototype 연결이 홈→문화→지역→장소→담기, 탐색→코스, 코스→AI 변경안 흐름을 보여준다.
- [ ] 지도·다국어 담당 경계와 R15 구현 제외 사항이 handoff에 적혀 있다.
- [ ] Flutter 구현자가 임의로 추측해야 하는 핵심 수치나 상태가 남지 않는다.
