## 1. R14의 목적과 경계

R14의 목적은 CulturePath의 정보구조와 시각 언어를 확정해 R15 Flutter 구현에서 다시 설계하지 않게 만드는 것이다. Manus는 독립형 모바일 프로토타입의 생성·반복 검증에 사용하고, 승인 결과는 최종 패키지의 디자인 시스템·상태·Figma handoff 문서로 정리한다. Figma 네이티브 원본은 필요할 때 후속 생성하며 R15 착수를 막지 않는다. 최종 판단은 실제 데이터·Flutter 구현 가능성·접근성을 기준으로 한다.

### 포함

- 홈·탐색의 정보구조 재편
- 현재 브랜드를 연결한 색·타입·간격·모서리·그림자·아이콘 토큰
- 홈·문화·지역·장소·탐색·코스·AI의 P0 화면과 주요 상태
- 390dp를 기준으로 360dp·430dp 폭 대응
- 화면별 Manus 프로토타입 프롬프트, Figma 최종 정리 프롬프트와 휴먼 디자인 검수 기준

### 제외

- 다국어 관광 API·locale 캐시·Flutter 기능 구현
- 지역 목록/지도 전환, 마커·카드 연동, 번호 마커, Day 순서선과 경로 계산
- Backend·Swagger·DB 스키마 변경
- OpenRouter live 연결과 RAG 품질 튜닝
- Manus·Figma 생성 결과를 검수 없이 바로 Flutter에 적용하는 작업

다국어와 지도 고도화는 임수민 담당이다. 황찬우는 해당 변경이 머지된 후 공통 디자인 일관성과 RAG `contentId` 호환성만 통합 확인한다.

## 2. 현재 Flutter 감사 결과

| 영역 | 현재 상태 | R14 판단 |
| --- | --- | --- |
| 하단 탐색 구조 | `홈 / 탐색 / 만들기 / 내정보` 4개 탭 | 유지한다. 기능 재배치는 하단 탭을 늘리지 않고 홈·탐색 내부에서 해결한다. |
| 홈 | 로고·검색·AI, 시즌 배너, 문화 10종 그리드 후 종료 | 문화 선택을 주인공으로 유지하고 하단에 `내 코스 이어보기`만 추가한다. |
| 탐색 | `피드 / 랭킹` 2개 탭 | `내 코스 / 커뮤니티 / 인기` 3개 탭으로 재구성한다. |
| 내 코스 | 프로필 하위 화면에만 있음 | 탐색 첫 탭과 홈의 작은 이어보기 섹션에서 즉시 접근하게 한다. |
| 코스 데이터 | `getMyCourses()`, guest 로컬 코스, feed, ranking이 이미 존재 | R14는 새 Backend를 가정하지 않는다. R15에서 기존 출처만 재사용한다. |
| 브랜드 | 딥 네이비·웜 크림·테라코타·머스타드, Noto Serif/Sans | 색과 폰트 개념은 유지하되 토큰과 사용 비율을 엄격히 한다. |
| 시각 패턴 | 둥근 카드·pill·원형 버튼·그라데이션·그림자 반복 | 정보 위계를 여백·선·타입과 실제 사진으로 만들고 장식을 줄인다. |
| AI 진입 | 홈 상단의 원형 `AI` 버튼 | AI를 앱의 주인공처럼 보이지 않게 하고, 코스 문맥에서 `AI로 다듬기`로 표현한다. |
| 이미지 | TourAPI HTTPS 이미지·상세·placeholder 계약 완료 | 편집물의 주요 시각 재료로 사용하되, 없어도 정보 구조가 붕괴하지 않게 한다. |

### 새 Backend 없이 사용 가능한 데이터

- 로그인 사용자 내 코스: `GET /courses`
- 게스트 코스: `SharedPreferences` 기반 `guest_courses`
- 커뮤니티: `GET /courses/feed?sort=recent|popular`
- 인기 코스: `GET /courses/ranking`
- 문화·지역·장소·상세·연관 장소: 기존 내부 API

내 코스 응답에는 Backend `createdAt`·`updatedAt`이 있지만 현재 Flutter `CourseItem`은 이를 보존하지 않는다. R14 시안은 `내 코스 이어보기`로 표현하고, R15에서 timestamp를 파싱하기 전에는 `방금 편집` 같은 정확한 시간 문구를 노출하지 않는다.

## 3. 정보구조

### 3.1 하단 탭

| 탭 | 역할 | 주요 행동 |
| --- | --- | --- |
| 홈 | 문화 취향으로 여행을 시작 | 검색, 문화 선택, 내 코스 이어보기 |
| 탐색 | 내 코스와 다른 사용자의 코스 탐색 | 내 코스 관리, 커뮤니티, 인기 코스 |
| 만들기 | 새 코스 작성 | 장소 담기, Day 구성, 저장 |
| 내정보 | 계정·저장·완주 정보 | 프로필, 좋아요, 설정 |

하단 탭은 고정한다. 중앙 `만들기`를 과도하게 튀어오르는 FAB처럼 만들지 않고 다른 탭과 같은 레벨의 목적지로 표시한다.

### 3.2 홈 순서

1. 브랜드 제목과 검색
2. 계절 편집 노트
3. `오늘은 어떤 문화를 따라갈까요?` 문화 10종 그리드
4. `내 코스 이어보기` 최대 2개
5. 하단 탭 전 충분한 바닥 여백

홈은 인기 코스를 다시 나열하지 않는다. 공개 코스는 탐색의 역할로 남겨 화면 목적을 분리한다.

#### 내 코스 이어보기 상태

- 로그인 + 코스 있음: 최대 2개와 `전체 보기`
- 로그인 + 코스 없음: 작은 빈 상태와 `첫 코스 만들기`
- 게스트 + 로컬 코스 있음: 로컬 코스 최대 2개와 `계속 편집`
- 게스트 + 로컬 코스 없음: `첫 코스 만들기`; 로그인 강요 배너는 노출하지 않음
- 로딩: 2개 skeleton row
- 실패: stale 데이터가 없으면 짧은 오류 문구와 `다시 시도`

### 3.3 탐색 순서

`ExploreScreen`은 다음 3개 탭을 가진다.

1. **내 코스**: 기본 탭. 로그인 코스 또는 게스트 로컬 코스
2. **커뮤니티**: 최신/인기 세그먼트 정렬을 가진 공개 코스 피드
3. **인기**: 점수 기반 랭킹과 순위

스위치로 `최신 ↔ 인기`를 표현하지 않고, 두 선택지가 동등하게 읽히는 세그먼트 컨트롤을 사용한다. `내 코스`는 상세 진입을 행 전체에 주고, 편집·삭제는 별도 overflow menu로 분리해 오터치를 줄인다.

## 4. 시각 방향: 문화 여행 편집물

### 핵심 문장

**종이 위에 여행 사진과 문화 기록을 편집한 모바일 잡지.**

사진, 지명, 문화 키워드, 일정 순서가 정보 위계를 만든다. 만든 이의 흔적은 절제된 선·주석·종이 질감의 느낌으로 드러나야 하며, 자동 생성 랜딩 페이지의 카드 모음처럼 보이면 안 된다.

### 사용한다

- 실제 관광지 사진과 단색 overlay
- 본명조 제목과 고딕 본문의 대비
- 얇은 구분선과 그리드 정렬
- 짧은 편집 주석, 순서 번호, 출처 표기
- 목적이 분명한 테라코타 액션

### 제한한다

- 한 화면에 강한 그라데이션 2개 이상
- 모든 정보를 독립된 둥근 카드에 넣는 구성
- 필터가 아닌 텍스트에 pill을 남용하는 구성
- 의미 없는 보라색·네온·반짝이 AI 표현
- 일러스트, emoji, 바꾼 아이콘으로 실제 이미지 부족을 숨기는 방식
- 실제 기능이 없는 일정·날씨·가격·거리 데이터

### 5.2 타이포그래피

| 역할 | 제안 | 기준 크기/line height |
| --- | --- | --- |
| Display | Noto Serif KR Bold | `28/38` |
| Screen title | Noto Serif KR Bold | `22/30` |
| Section title | Noto Serif KR SemiBold | `18/26` |
| Card title | Noto Sans KR SemiBold | `15/22` |
| Body | Noto Sans KR Regular | `14/22` |
| Label | Noto Sans KR Medium | `12/18` |
| Caption | Noto Sans KR Regular | `11/16`; 필수 정보에 11dp 미만 금지 |

제목을 제외한 부분에 명조를 남용하지 않는다. Android에서 폰트 로딩이 느리거나 실패해도 레이아웃이 붕괴하지 않는 fallback을 전제한다.

### 5.3 간격·모서리·그림자

- 간격 기본 단위: `4`
- 사용 스케일: `4, 8, 12, 16, 20, 24, 32, 40`
- 화면 수평 여백: 390dp에서 `20`, 360dp에서 `16`, 430dp에서 `24`
- 버튼 radius: `10`
- 입력·작은 표면 radius: `8`
- 사진 카드 radius: `12`; 내부 요소는 중복 radius를 줄임
- pill: 선택 필터·상태 배지에만 사용
- 기본 카드: 그림자 없음 + `line` 1dp 또는 배경 면 차이
- 부유 표면: 중요한 모달·bottom sheet에만 blur `12`, alpha `0.08`

### 5.4 터치·아이콘·모션

- 모든 터치 영역: 최소 `44×44dp`
- 일반 아이콘: `20·24dp`; 보조 아이콘 `16dp`
- 화살표나 `+`만으로 행동을 숨기지 않고 필요할 때 텍스트 label 제공
- 페이지 전환: 180~240ms
- 선택·좋아요: 120~180ms
- 장식용 무한 애니메이션 금지
- `reduce motion`을 고려해 애니메이션 없이도 상태를 이해할 수 있게 함

## 7. P0 화면 명세

### 7.1 홈

- 상단: 브랜드 제목, 검색 진입. AI 원형 버튼은 제거하거나 보조 menu로 낮춤
- 계절 노트: 그라데이션 hero 대신 한 장의 사진·단색 overlay·짧은 편집 문구
- 문화 그리드: 2열, 문화 10종. 페이지 첫 목적이며 배너보다 정보 비중이 높아야 함
- 내 코스: 세로 행 최대 2개, `전체 보기`, 빈 상태 CTA
- 스크롤 끝: 하단 탭과 콘텐츠가 붙어 보이지 않는 24dp 이상 여백

### 7.2 탐색

- 헤더: `탐색`, 검색
- 1차 탭: `내 코스 / 커뮤니티 / 인기`
- 내 코스: 소유자 행, 상세 진입, overflow의 편집·삭제. 게스트도 로컬 코스를 볼 수 있음
- 커뮤니티: `최신 / 인기` 세그먼트, 피드 카드, 좋아요
- 인기: 1~3위와 나머지를 색·여백으로 구분하되 메달·원형 배지를 과장하지 않음
- 각 탭: loading, empty, error, stale 상태

### 7.3 문화 상세·지역 상세

- 문화 상세: 문화명·설명·추천 지역 순위·이유·장소 수
- 공개 API에 없는 정밀 점수나 즉시 변하는 실시간 문구를 발명하지 않음
- 지역 상세: 선택한 `문화 × 지역` 문맥, 실제 사진·주소·운영시간·담기·상세 진입
- 장소 카드의 사진/제목 탭과 `담기` 행동을 분리
- 지도 기능·토글·마커는 시안에서 새로 설계하지 않음

### 7.4 장소 상세

- 260dp 이미지 갤러리, 현재 인덱스·출처
- 문화 분류, 장소명, 주소·운영시간·휴무·전화·주차·홈페이지
- 소개는 읽기 편한 line height와 최대 폭을 사용
- 연관 방문 장소는 수평 사진 타일; 별도 상세로 진입
- `이 장소를 코스에 담기`는 한 번만 분명하게 노출

### 7.5 코스 만들기·상세

- Day 1~3을 음악 셋리스트처럼 보이되 음악 앱을 흉내 내지 않음
- 순서, 장소명, 지역, 문화, 편집 행동이 가장 먼저 읽혀야 함
- 빈 Day, 장소 검색 중, 저장 중, 저장 실패, Fork 원본 크레딧 상태
- 지도 고도화는 임수민 담당이다. 지도 영역을 새로 발명하지 않고 기존 위치의 시각 일관성만 본다.

### 7.6 AI 변경안

- AI의 답변 버블보다 `요청 요약 → 변경 전/후 → 경고 → 적용/취소`가 중심
- `AI로 다듬기`라는 행동 언어 사용
- 추가·제거·이동·유지를 색만으로 구분하지 않고 아이콘·라벨·설명을 함께 사용
- 적용 전에 원본이 보존된다는 점, 적용 후 원본 복구 행동을 분명히 표시
- OpenRouter·Qdrant 오류를 기술 용어 대신 재시도 가능한 사용자 언어로 표시

## 8. 반응형·Android 규칙

| 폭 | 규칙 |
| --- | --- |
| 360dp | 수평 여백 16, 2열 그리드 유지, 카드 내 보조 문구 최대 1~2줄, 행동은 아이콘만으로 축소하지 않음 |

| 430dp | 수평 여백 24, 텍스트 줄 길이를 무제한으로 늘리지 않고 카드·그리드 폭만 조정 |

- status bar·navigation gesture 영역과 bottom navigation safe area를 포함한다.
- text scale `1.0`, `1.3`, `2.0`을 검수한다. 2.0에서는 2열 카드의 보조 문구를 줄이더라도 제목과 행동은 유지한다.
- 시스템 뒤로가기, 스크롤 복원, 키보드 표시 시 CTA 가림을 고려한다.
- 작은 화면에서 터치 영역을 줄이지 않고 세로 여백·보조 텍스트를 조정한다.

## 9. 상태 명세

| 상태 | 제품 표현 |
| --- | --- |
| 초기 loading | 구조가 고정된 skeleton; 전체 화면 spinner 반복 금지 |
